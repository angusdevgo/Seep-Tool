## 🎯 核心要点速览

### 五阶段标准流程

```
① 发现与验证 (Discovery & Validation)
   └─ 在受权环境验证，记录最小必要证据
        ↓
② 私下通知厂商 (Private Notification)
   └─ 通过官方安全邮箱，提供缺陷描述 + 影响 + 修复建议
        ↓
③ 协商修复期 (Coordinated Fix Window)
   └─ 默认 90 天，复杂缺陷可协商延长
        ↓
④ 协调公开 (Coordinated Disclosure)
   └─ 修复后协商公开，以「缺陷描述 + 修复方案」为主
        ↓
⑤ 归档与致谢 (Archive & Credit)
   └─ 可申请 CVE 编号
```

### 公开内容的边界

| 应包含 ✅ | 不应包含 ❌ |
|:---|:---|
| 缺陷类别与 CWE 编号 | 完整利用代码 |
| 架构层根因分析 | 精确偏移与补丁字节 |
| 影响范围 | 一键绕过工具 |
| 修复方案 | 大规模利用方法 |
| 厂商致谢 | — |

### 四条道德底线

1. **不获取数据** —— 不读取、不下载、不外传任何用户或商业数据
2. **不造成损害** —— 不破坏系统、不影响他人使用
3. **不公开利用** —— 不发布可运行的攻击代码或工具
4. **不谋取私利** —— 不以漏洞要挟、勒索或非法牟利

## 📌 与本仓库公告的关系

`docs/04-安全公告/` 中的全部公告**均按本目录规范编写**：

- ✅ 包含：受影响版本、缺陷分类、架构根因、修复建议
- ❌ 不含：精确偏移、补丁字节、绕过步骤、可执行工具
