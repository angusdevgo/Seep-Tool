## ➕ 如何新增内容

### 新增一篇理论/防御文档

在对应类型文件夹下新建 `.md` 文件，按序号命名：

```
docs/01-理论基础/03-新增文档名.md
docs/02-防御体系/04-新增文档名.md
```

### 新增一款产品的安全公告

1. **确定其缺陷模式**（可多选）→ 进入对应模式文件夹；
2. **在模式文件夹下新建 `{产品名}.md`**，按七字段模板撰写：

```markdown
# {产品名} · {缺陷模式}

| 字段 | 内容 |
|:---|:---|
| **受影响组件** | {具体模块/DLL/EXE 名} |
| **缺陷类别** | `CWE-xxx` {类别名} |
| **风险等级** | 🔴 高 / 🟠 中高 / 🟡 中 |
| **对应模式** | 模式 N（{模式名}） |

### 架构层根因分析
{为什么这样设计会出问题}

### 影响面
{业务与安全后果}

### 审计要点
{可推广的通用审计方法}

### 加固方案
| 层级 | 措施 |
|:---|:---|
| **架构** | {架构修正} |
| **密码学** | {算法迁移} |
| **运行时** | {加固手段} |
```

3. **同步更新三处**：
   - 本文件（`docs/README.md`）的快速导航表
   - `docs/04-安全公告/README.md` 的总览矩阵与统计
   - 对应模式文件夹的 `README.md` 成员表
   - 若为**新缺陷模式**，另需在 `01-理论基础/02-客户端脆弱性模式矩阵.md` 补充模式定义

> ⚠️ **合规红线**：公告只写**根因 / 影响 / 修复方案**，
> **严禁**写入偏移地址、补丁字节、绕过步骤或任何可运行脚本。
