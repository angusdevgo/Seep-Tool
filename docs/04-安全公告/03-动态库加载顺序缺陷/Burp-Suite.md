# Burp Suite Professional · 单点布尔裁决

> **公告编号**：03
> **缺陷模式**：模式 01 · 单点布尔裁决（兼 模式 03）
> **关联 CWE**：`CWE-602` · `CWE-427`
> **风险等级**：🟠 中高（含**代码执行类**缺陷）
> **披露状态**：待联系厂商
> **最后更新**：2026-10

## 摘要

Burp Suite Professional 采用 **原生启动器 + Java 运行时** 的混合架构，
其授权链路在两个层级上均存在缺陷：

1. **原生层**：启动器的动态库加载链不受控（CWE-427），
   可被用于在合法进程中取得原生代码执行权；
2. **JVM 层**：虚拟机支持通过**启动参数动态加载 Agent**，
   一旦原生层被控制，即可在**字节码层面**改写授权状态机 ——
   且**完全不修改官方二进制文件**，传统文件完整性校验无法察觉。

## 攻击接入点分析 ★

### 接入点清单

| # | 接入点 | 所在组件 / 机制 | 攻击者前提 | 可获得能力 | 影响 |
|:---:|:---|:---|:---|:---|:---:|
| **AP-1** | **原生启动器加载链** | 启动器对同目录/相对路径动态库的加载调用 | 对安装目录有写权限 | **原生层代码执行** | 🔴 严重 |
| **AP-2** | **JVM 启动参数注入面** | `JNI_CreateJavaVM` 调用点的 `JavaVMInitArgs` | 控制原生层（AP-1）或启动配置 | 向 JVM 注入自定义 `-javaagent` | 🔴 严重 |
| **AP-3** | **授权状态机（字节码层）** | JVM 内负责准入判定的类与方法 | 已注入 Agent（AP-2） | **运行时改写授权判定**，解锁全部专业功能 | 🔴 高 |
| **AP-4** | **注册表授权偏好与令牌** | 授权状态与 AI ActivationToken 的本地存储 | 用户态注册表写权限 | 直接播种"已授权"状态 | 🔴 高 |
| **AP-5** | **JAR 包完整性** | 官方 JAR 无可执行签名校验 | 文件级替换权限 | 持久化改写（重启仍生效） | 🟠 中高 |

| 类型 | 接入点 | 说明 |
|:---|:---|:---|
| **代码执行类** | AP-1 · AP-2 | 🔴 最高危 —— 且与授权无关，本身即安全漏洞 |
| **运行时改写类** | AP-3 | **不触碰磁盘文件** → 取证与检测难度极高 |
| **状态播种类** | AP-4 | 直接写入本地授权状态 |
| **持久化类** | AP-5 | 重启后仍生效 |

### 攻击链组合分析

| 攻击链 | 组合路径 | 门槛 | 最终效果 |
|:---|:---|:---:|:---|
| **链 A**（最高危） | **AP-1 → AP-2 → AP-3** | 中 | **原生代码执行 + 字节码层授权改写**，且**磁盘文件零修改** |
| **链 B**（免代码注入） | AP-4 直接播种授权状态 | **低** | 专业版功能解锁 |
| **链 C**（持久化） | AP-5 替换 JAR | 中 | 重启后持续生效 |

> ⚠️ **链 A 的独特危险点**：`AP-3` 的改写发生在**内存中的字节码**，
> **完全不触碰磁盘上的官方二进制** ——
> 这意味着基于**文件哈希/签名校验**的完整性检测机制**完全失效**。
> 传统取证手段（比对文件哈希）无法发现任何异常。

### 攻击面收敛建议（厂商视角）

```
接入点优先级（按风险排序）

  AP-1  代码执行类    ──→ 最高优先（启动器限定加载路径 + 自签名校验）
  AP-2  参数注入类    ──→ `-javaagent` 来源白名单 + 启动参数完整性校验
  AP-4  状态播种类    ──→ 授权状态改由服务端签名凭据承载
  AP-3  运行时改写类  ──→ 关键判定下沉 Native 并做完整性自检
  AP-5  持久化类      ──→ 启用 JAR 签名校验 + 类加载器白名单
```

## 技术细节

### 1 · 原生层：加载链不受控

**观测事实**：启动器负责定位并拉起 JVM，
但**未对自身加载的动态库做路径限定与签名校验**。

**安全含义**：构成 **CWE-427** 缺陷 —— 与 02 号案例同类。
攻击者获得原生层代码执行权后，**后续所有 JVM 层操作都无需独立突破**。

---

### 2 · JVM 层：启动参数成为注入面

**观测事实**：Java 虚拟机设计上支持通过**启动参数动态加载 Agent**
（`-javaagent` 机制），这是 JVM 的**合法扩展能力**。

**安全含义**：

| 维度 | 说明 |
|:---|:---|
| 机制性质 | JVM 的标准扩展点，本身非缺陷 |
| 风险来源 | **原生层被控制后**，该扩展点成为稳定的注入通道 |
| 关键问题 | 产品未校验 `-javaagent` 的来源白名单 |
| 后果 | 可在 JVM 启动前注入任意字节码改写器 |

**结论**：这是"**上游失守导致下游机制被滥用**"的典型案例。

---

### 3 · 字节码层：授权状态机可被运行时改写

**观测事实**：授权准入由 JVM 内特定类的方法决定，
且**存在可写状态字段**，缺乏运行时完整性保护。

**安全含义**：

1. **不触碰磁盘**：改写发生在内存中的类字节码 → 文件哈希校验无法发现；
2. **检测困难**：不产生文件修改痕迹，取证需依赖**内存快照**或**类加载监控**；
3. **稳定可重复**：一旦注入通道建立，改写过程完全可重复。

**核心教训**：**混合架构（原生 + 托管）中，安全强度取决于最弱的那一层。**

---

### 4 · 状态层：授权状态可本地播种

**观测事实**：授权状态与令牌存储在用户可写的注册表位置，
**读取时无完整性校验**。

**安全含义**：无需任何代码注入，**仅靠配置写入即可影响授权状态**。

## 影响面

### 商业影响

- 专业版全部功能（含漏洞扫描器）可被解锁；
- 由于不触碰磁盘文件，**厂商难以通过文件校验发现异常**；
- 授权状态可本地播种，商业保护能力丧失。

### 安全影响

- 🟠 **原生层任意代码执行** —— 与授权问题无关的独立风险；
- 字节码层改写破坏 JVM 的类加载信任模型；
- 检测难度高，企业环境中的取证与响应成本显著上升。

### 合规影响

- 作为安全工具本身存在加载链缺陷，可能影响企业安全基线评估；
- 运行时改写无文件痕迹，不满足部分安全审计的可追溯性要求。

## 加固方案

### 1 · 原生层加固（最高优先级）

```cpp
// ✅ 启动器入口点首行
int wmain()
{
    SetDefaultDllDirectories(
        LOAD_LIBRARY_SEARCH_SYSTEM32 |
        LOAD_LIBRARY_SEARCH_APPLICATION_DIR);

    // 自身完整性自校验
    if (!VerifySelfAuthenticode())  return -1;
    if (!VerifySelfCodeHash())      return -1;

    return LaunchJvm();
}
```

### 2 · JVM 层加固

```java
// ✅ 启动参数来源白名单校验（在创建 JVM 前执行）
static void validateVmArgs(List<String> args) {
    for (String a : args) {
        if (a.startsWith("-javaagent:")) {
            String agentPath = a.substring("-javaagent:".length());
            // 1) 必须位于受信任目录
            if (!isTrustedDir(agentPath)) throw new SecurityException("Agent 路径不受信");
            // 2) 必须通过签名校验
            if (!verifyAgentSignature(agentPath)) throw new SecurityException("Agent 签名无效");
        }
    }
}
```

**同时启用**：
- JAR 签名校验（`jarsigner -verify` 逻辑内置到启动流程）；
- 类加载器监控，检测运行时字节码篡改；
- 关键判定逻辑下沉 Native 层，并对其做完整性校验。

### 3 · 状态层加固

| 措施 | 说明 |
|:---|:---|
| 授权状态凭据化 | 改为服务端签名凭据，不以本地注册表为准 |
| 令牌完整性校验 | 读取后验签，失败即拒绝 |
| Fail-Closed | 校验不确定时按未授权处理 |

### 4 · 加固优先级

```
第一优先
  └─ 启动器加载路径限定 + 自签名/自哈希校验      ← 消除 AP-1 / AP-2

第二优先
  ├─ 授权状态改服务端签名凭据                     ← 消除 AP-3 / AP-4
  └─ JAR 签名校验 + 类加载器白名单                ← 消除 AP-5

第三优先
  └─ 运行时字节码完整性监控
```
