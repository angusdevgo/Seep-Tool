# 教学靶场 · SeepLab

> **CWE-602 客户端鉴权脆弱性 · 缺陷模式演示与二进制点位分析**
>
> 本目录提供一个**自建示例程序**（`SeepLab`），它**故意植入 6 种鉴权缺陷模式**。
> 读者通过对它做静态分析与二进制修改，可以完整走通
> 「**源码 → 编译 → 汇编/IL → 文件偏移 → 字节修改 → 效果验证**」这条链路。
>
> ⚠️ **本靶场是自建样本**（MIT 协议），**不含任何真实产品的实现细节**。
> 其价值在于：教会读者**识别缺陷模式的方法**，而非提供针对特定产品的答案。

---

## 一、 为什么需要靶场？

真实产品的二进制分析存在三个障碍：

| 障碍 | 说明 |
|:---|:---|
| **版本漂移** | 点位随版本变化，昨天有效的偏移今天可能失效 |
| **保护层干扰** | 混淆、虚拟化、反调试会掩盖缺陷本身的形态 |
| **无源码对照** | 看不到源码，就难以理解"这条指令对应哪一行逻辑" |

**靶场解决的正是这三点**：

* 源码全公开 → 能看懂每条指令的**设计意图**
* 无保护层 → 能专注理解**缺陷本身的形态**
* 可控可重建 → 随时编译出对照样本，**验证自己的理解**

**学完之后**，读者带着这套方法去看任何真实产品，都能自己定位。

## 二、 快速开始

### 1. 编译（零依赖）

```powershell
cd "docs\05-教学靶场"
powershell -ExecutionPolicy Bypass -File .\build.ps1
```

> 💡 使用 Windows 自带的 .NET Framework 4.x 编译器，
> **无需安装 Visual Studio / .NET SDK / 任何包**。

### 2. 运行

```powershell
.\SeepLab.exe            # 列出全部模式
.\SeepLab.exe 01         # 模式 01 · 单点布尔裁决
.\SeepLab.exe 02         # 模式 02 · 硬编码密钥材料
.\SeepLab.exe 03         # 模式 03 · 动态库加载顺序缺陷
.\SeepLab.exe 03 <PE>    # 对任意 PE 做导入表审计（真实审计器）
.\SeepLab.exe 04         # 模式 04 · 可写全局状态变量
.\SeepLab.exe 05         # 模式 05 · 明文进程间通信
.\SeepLab.exe 07         # 模式 07 · 空值短路校验（Fail-Open）
.\SeepLab.exe all        # 依次运行全部
```

## 四、 靶场覆盖的 6 种缺陷模式

| 模式 | 源码文件 | 核心缺陷 |
|:---|:---|:---|
| **01 单点布尔裁决** | `Pattern01_SinglePointBool.cs` | 授权状态为一个静态可写布尔量，被 3 处业务逻辑直接读取 |
| **02 硬编码密钥材料** | `Pattern02_HardcodedKey.cs` | 信任根（公钥）无完整性保护，可被原位置换 |
| **03 动态库加载顺序缺陷** | `Pattern03_DllSearchOrder.cs` | 裸 `LoadLibrary` + 缺失 `SetDefaultDllDirectories` |
| **04 可写全局状态变量** | `Pattern04_WritableGlobalState.cs` | 权益判据存放在注册表/配置/环境变量等用户可写位置 |
| **05 明文进程间通信** | `Pattern05_PlaintextIpc.cs` | 鉴权结果通过无认证的 IPC 通道传递 |
| **07 空值短路校验** | `Pattern07_FailOpen.cs` | 凭据缺失被当作"无需校验"→ 免检通道 |

> 💡 **模式 06（自研弱校验算法）** 未做独立靶场 ——
> 它的演示需要完整实现一套密码学算法，与"二进制点位"教学主题不符。
> 相关原理见 [模式矩阵](../01-理论基础/02-客户端脆弱性模式矩阵.md)。

## 五、 每个点位文档包含什么

```
patch-points/0N-模式名.md
├── 1. 靶场程序信息          ← 源码位置、编译命令、SHA256
├── 2. 缺陷成因（源码层）     ← 对应源码、逐行讲解
├── 3. 二进制分析            ← 关键字符串偏移、方法元数据偏移
├── 4. 完整点位表 ★          ← 偏移 / 原始字节 / 修补字节 / 效果
├── 5. 定位方法              ← 如何在 IDA/dnSpy 中自己找到这些点位
├── 6. 验证步骤              ← 修改后如何确认生效
├── 7. 回滚方式              ← 如何恢复原始状态
├── 8. 软件归属对照表 ★      ← 该模式在哪些真实产品中出现、落在哪一层
└── 9. 防御加固方案          ← 对应的正确实现
```

## 六、 常见失败原因（对照真实分析场景）

| 现象 | 原因 | 处置 |
|:---|:---|:---|
| 偏移处字节与文档不符 | 编译器版本/优化级别不同 | 按「定位方法」重新定位 |
| 改了字节但无效果 | 改的是 UI 层而非权益闸门 | 用 `03` 模式的方法做导入表审计，确认真正的判定点 |
| 重启后状态回滚 | 状态被重新写入 | 参考模式 04 的"持久化"讨论 |
| 只改了一处仍不生效 | 多点交叉校验 | 参考模式 02 的"多点引用"设计 |
| 程序无法启动 | 破坏了 PE 结构或校验和 | 回滚备份，重新定位 |
