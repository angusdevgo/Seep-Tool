## 2. 缺陷成因（源码层）

### 2.1 缺陷核心

```cpp
// ❌ 错误写法：裸 LoadLibrary，未限定搜索路径
HMODULE h = LoadLibrary(L"helper.dll");
// Windows 搜索顺序：应用目录优先 → 同目录放一个 helper.dll 即可劫持
```

### 2.2 Windows DLL 搜索顺序（攻击原理）

```
应用调用 LoadLibrary("helper.dll") 时的搜索顺序：

  1. 应用所在目录           ← ★ 攻击点（普通用户常可写）
  2. 系统目录 (System32)
  3. 16 位系统目录
  4. Windows 目录
  5. 当前工作目录           ← ★ 攻击点
  6. PATH 环境变量中的目录    ← ★ 攻击点
```

**攻击者只需在位置 ① 放置同名 DLL**，即可在**合法签名进程**内执行代码。
**由于进程签名合法，常规安全软件通常不告警。**

### 2.3 正确写法

```cpp
// ✅ 入口点首行必须调用
int wmain()
{
    SetDefaultDllDirectories(
        LOAD_LIBRARY_SEARCH_SYSTEM32 |
        LOAD_LIBRARY_SEARCH_APPLICATION_DIR);

    // 加载非系统库：绝对路径 + 签名校验
    HMODULE h = LoadLibraryExW(
        L"C:\\Program Files\\App\\plugin.dll",
        nullptr,
        LOAD_LIBRARY_SEARCH_SYSTEM32 | LOAD_LIBRARY_SEARCH_APPLICATION_DIR);

    if (!h || !VerifyAuthenticode(h)) return -1;   // 拒绝启动
    return Run();
}
```

> ### 🔑 核心教训
> **本缺陷的严重性是「代码执行级」，高于大多数授权缺陷本身。**
> 它意味着**即使对完全不在意授权的用户也真实存在风险** ——
> 任何获得目录写权限的本地攻击者（含其他恶意软件）都能利用它。

## 4. 完整点位表 ★

> ⚠️ 本模式的"点位"与模式 01/02 不同 ——
> **CWE-427 的本质是「缺少防护调用」，而不是「存在可修改的判定指令」。**
> 因此点位表分为两部分：**（A）审计点位**（用于判定）；**（B）加固点位**（用于自我修复）。

### 4.1 A 组 · 审计点位（判定是否存在缺陷）

| # | 检查目标 | 数据来源 | 判定标准 | 结论 |
|---:|:---|:---|:---|:---|
| **P1** | `LoadLibrary` 导入 | PE 导入表函数名表 | 存在 | 有动态加载 |
| **P2** | `SetDefaultDllDirectories` 导入 | PE 导入表函数名表 | **缺失** = 🔴 高危 | 未限定路径 |
| **P3** | `LoadLibraryEx` 导入 | PE 导入表函数名表 | 存在时需检查第 3 参数 | 可能已限定 |
| **P4** | `WinVerifyTrust` 导入 | PE 导入表函数名表 | 缺失 = 🟠 未校验签名 | 加固缺失 |

**定位实现**：在 PE 原始字节中搜索函数名的 ASCII 序列（见源码 `HasImport` 方法）。

### 4.2 B 组 · 加固点位（在自有产品中补上防护）

| # | 加固位置 | 措施 | 效果 |
|---:|:---|:---|:---|
| **G1** | 程序入口点首行 | `SetDefaultDllDirectories(...)` | 从根源切断搜索顺序劫持 |
| **G2** | 非系统库加载处 | `LoadLibraryExW` + 绝对路径 | 不使用搜索顺序 |
| **G3** | 模块加载后 | `WinVerifyTrust(模块路径)` | 拒绝未签名/被替换的模块 |
| **G4** | 校验失败时 | `return -1` / `ExitProcess` | **Fail-Closed，拒绝启动** |

> ### ⚠️ 关键点：G4 不可省略
> 很多产品的加固只是"记录一条警告然后继续运行" ——
> **那等于没有加固**。校验失败必须**拒绝启动**。

### 4.3 与模式 01/02 的对照

| 维度 | 模式 01/02（判定类缺陷） | 模式 03（缺失类缺陷） |
|:---|:---|:---|
| 缺陷形态 | 存在**可被修改**的判定指令 | 存在**缺失的防护调用** |
| 攻击方式 | 修改字节 / 改控制流 | 放置同目录同名 DLL |
| 修复方式 | 改代码逻辑 | 加一行调用 |
| 修复成本 | 中 ~ 高（架构级） | **极低（一行）** |
| 风险等级 | 商业级 | **代码执行级** |

> 💡 **本模式是"投入产出比最高"的加固项** ——
> **一行代码，消除一个代码执行级漏洞。**

## 5. 定位方法

### 5.1 快速判定（推荐：用 dumpbin）

```powershell
# 需要 Visual Studio 或 Windows SDK 中的 dumpbin.exe
dumpbin /imports "C:\Path\To\Target.exe" | Select-String "LoadLibrary|SetDefaultDllDirectories|WinVerifyTrust"
```

### 5.2 无 dumpbin 时的替代方案

```powershell
# 方法 1：用靶场自带的审计器（无需任何工具）
.\SeepLab.exe 03 "C:\Path\To\Target.exe"

# 方法 2：Python 直接解析字节
python -c "
data = open(r'C:\Path\To\Target.exe','rb').read()
for api in ['LoadLibrary','SetDefaultDllDirectories','WinVerifyTrust','LoadLibraryEx']:
    print(f'{api:30s}', '存在' if data.find(api.encode())>=0 else '缺失')
"
```

### 5.3 在 IDA / x64dbg 中定位调用点

```
1. 在 IDA 中打开目标，查看 Imports 窗口
2. 找到 LoadLibrary 条目，按 X 查看交叉引用
3. 逐个检查调用点：
   - 参数是【字符串常量相对路径】→ 高危
   - 参数是【绝对路径】→ 相对安全
4. 检查入口点是否调用了 SetDefaultDllDirectories
```

## 9. 防御加固方案

### 9.1 完整加固代码

```cpp
#include <windows.h>
#include <wintrust.h>
#include <softpub.h>

// ✅ 步骤 1：入口点首行限定搜索路径
int wmain(int argc, wchar_t** argv)
{
    SetDefaultDllDirectories(
        LOAD_LIBRARY_SEARCH_SYSTEM32 |
        LOAD_LIBRARY_SEARCH_APPLICATION_DIR);

    // ✅ 步骤 2-4：安全加载模块
    if (!LoadSecureModule(L"C:\\Program Files\\App\\plugin.dll"))
    {
        return -1;                    // Fail-Closed：拒绝启动
    }

    return Run();
}

// ✅ 安全加载封装
HMODULE LoadSecureModule(const wchar_t* absPath)
{
    // 步骤 3：校验签名
    if (!VerifyAuthenticode(absPath))
    {
        LogError(L"模块签名校验失败: %s", absPath);
        return nullptr;
    }

    // 步骤 2：绝对路径 + 标志位加载
    return LoadLibraryExW(absPath, nullptr,
        LOAD_LIBRARY_SEARCH_SYSTEM32 | LOAD_LIBRARY_SEARCH_APPLICATION_DIR);
}

bool VerifyAuthenticode(const wchar_t* path)
{
    WINTRUST_FILE_INFO fileInfo = {};
    fileInfo.cbStruct = sizeof(fileInfo);
    fileInfo.pcwszFilePath = path;

    WINTRUST_DATA data = {};
    data.cbStruct = sizeof(data);
    data.dwUIChoice = WTD_UI_NONE;
    data.fdwRevocationChecks = WTD_REVOKE_NONE;
    data.dwUnionChoice = WTD_CHOICE_FILE;
    data.pFile = &fileInfo;
    data.dwStateAction = WTD_STATEACTION_VERIFY;

    GUID policy = WINTRUST_ACTION_GENERIC_VERIFY_V2;
    LONG status = WinVerifyTrust(nullptr, &policy, &data);

    data.dwStateAction = WTD_STATEACTION_CLOSE;
    WinVerifyTrust(nullptr, &policy, &data);

    return status == ERROR_SUCCESS;
}
```

### 9.2 加固检查清单

- [ ] 入口点首行调用了 `SetDefaultDllDirectories`
- [ ] 无裸 `LoadLibrary` 调用（全部使用 `LoadLibraryExW` + 绝对路径）
- [ ] 所有非系统模块执行了 `WinVerifyTrust` 校验
- [ ] 校验失败时**拒绝启动**（而非继续运行）
- [ ] 定期用 `dumpbin /imports` 复核上述四项

### 9.3 加固优先级

```
最高优先（成本最低，收益最高）★
  ├─ 入口点加 SetDefaultDllDirectories        ← 一行代码
  └─ 非系统模块改绝对路径加载

第二优先
  ├─ 模块签名校验（WinVerifyTrust）
  └─ 校验失败时拒绝启动（Fail-Closed）

第三优先
  └─ 定期自动化审计（CI 集成 SeepLab.exe 03）
```
