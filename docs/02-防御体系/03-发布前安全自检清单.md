# 05 · 发布前安全自检清单

> 桌面软件上线前必过的 **20 项客户端安全基准**。
> 建议纳入 CI/CD 流程，作为发布门禁（Release Gate）。

---

## 使用方式

```
发布前 → 逐项自检 → 全部通过 → 允许发版
                  → 存在 🔴 项 → 阻断发版
```

**风险标记说明**：
- 🔴 **阻断级**：必须修复，否则不得发版
- 🟠 **高优先级**：强烈建议修复
- 🟡 **建议级**：视成本修复

---

## A 组 · 授权架构（最高优先级）

### A1 🔴 是否存在客户端独立裁决授权状态？

**自检方法**：搜索代码中是否存在形如 `IsPro()`、`IsLicensed()`、`IsActivated()`
的独立函数，且其返回值直接控制功能开关。

```csharp
// ❌ 命中即不合格
if (LicenseManager.IsPro()) { AdvancedFeature(); }
```

- [ ] 无独立布尔判定出口
- [ ] 授权校验与功能执行**合一**
- [ ] 无"先判后用"的中间状态

---

### A2 🔴 客户端是否内置了私钥或对称密钥？

**自检方法**：搜索二进制中的密钥常量、`AesKey`、`PrivateKey`、Base64 长字符串。

- [ ] 客户端**仅**内置公钥
- [ ] 无私钥材料（含硬编码、资源文件、配置文件）
- [ ] 无对称加密密钥用于凭据解密

---

### A3 🔴 授权凭据是否由服务端签名？

- [ ] 凭据包含**非对称签名**（Ed25519 / RSA-PSS / ECDSA）
- [ ] 客户端仅做**验签**，不参与签发
- [ ] 私钥存于服务端 HSM / 离线机

---

### A4 🔴 是否存在自研密码学算法？

**自检方法**：搜索"多项式哈希""查表异或""自研编码""混合哈希"等实现。

- [ ] 全部使用**标准密码学原语**
- [ ] 无自研哈希 / 加密 / 编码算法
- [ ] 已建立"禁止自研密码学"的代码审查红线

---

### A5 🟠 授权凭据是否绑定设备？

- [ ] 凭据载荷包含 `deviceHash`
- [ ] 设备指纹由**多个硬件标识组合**（非单一）
- [ ] 绑定关系经过**密码学保护**（在签名载荷内）

---

### A6 🟠 是否校验授权有效期与防时钟回拨？

- [ ] 载荷含 `issuedAt` / `expiresAt`
- [ ] 实现**单调时钟**（记录历史最大时间值）
- [ ] 检测到时间回拨时拒绝运行或降级

---

## B 组 · 加载与运行时安全

### B1 🔴 是否调用了 `SetDefaultDllDirectories`？

**自检方法**：检查程序入口点（`main` / `wmain` / `WinMain`）首几行。

```cpp
// 必须存在
SetDefaultDllDirectories(
    LOAD_LIBRARY_SEARCH_SYSTEM32 | LOAD_LIBRARY_SEARCH_APPLICATION_DIR);
```

- [ ] 入口点首行调用 `SetDefaultDllDirectories`
- [ ] 无裸 `LoadLibrary` 调用
- [ ] 加载第三方库使用**绝对路径**

---

### B2 🔴 加载的动态库是否做了签名校验？

- [ ] 所有非系统库执行 `WinVerifyTrust` 校验
- [ ] 拒绝未签名 / 签名不符的模块
- [ ] 校验失败时**安全退出**（不降级运行）

---

### B3 🟠 是否有二进制完整性自检？

- [ ] 运行时校验自身 Authenticode 签名
- [ ] 关键代码段哈希与编译期预置值比对
- [ ] 在**多个时机**重复校验（启动 / 关键操作前 / 定时）

---

### B4 🟠 敏感数据是否加密存储且用毕擦除？

- [ ] 敏感数据在堆中**加密存储**
- [ ] 使用 `CryptographicOperations.ZeroMemory` 立即清零
- [ ] 使用 `VirtualLock` 防止敏感页换出到磁盘
- [ ] **不缓存**授权布尔结果

---

### B5 🟠 进程间通信是否做了消息认证？

- [ ] IPC 消息附带 **HMAC**
- [ ] 消息含**时戳 + 序号**（防重放）
- [ ] 校验**对端进程身份**（路径 + 签名）
- [ ] 管道 / 共享内存设置 **ACL 限制**

---

### B6 🟡 是否实施了反调试 / 反注入？

- [ ] PEB 调试标志检测
- [ ] 时间差异常检测
- [ ] 内存完整性检测
- [ ] 注意：**不得因误报影响正常用户**（虚拟机、低配机）

---

## C 组 · 网络与传输安全

### C1 🔴 是否强制 HTTPS？

- [ ] 禁用 HTTP 回退
- [ ] 启用 HSTS
- [ ] 拒绝无效 / 过期证书

---

### C2 🟠 是否实施证书绑定（Certificate Pinning）？

- [ ] 内置服务端证书 / 公钥指纹
- [ ] 校验失败时拒绝连接
- [ ] 有证书轮换预案

---

### C3 🟠 请求是否带签名与防重放？

- [ ] 每个请求含 `HMAC(请求体 + 时戳 + Nonce)`
- [ ] 服务端校验 Nonce 唯一性
- [ ] 拒绝超时请求（如 > 5 分钟）

---

### C4 🟠 云端校验通道是否防阻断？

- [ ] 使用 **HTTPS + 证书绑定**（而非明文 HTTP）
- [ ] 关键响应**由服务端签名**，客户端验签
- [ ] 通道异常时**不静默降级**为"信任本地状态"

---

## D 组 · 代码形态与信息保护

### D1 🟠 是否剥离了调试符号与敏感字符串？

- [ ] Release 构建剥离 PDB 符号
- [ ] 移除有意义的函数 / 变量名
- [ ] 敏感字符串加密存储，运行时解密
- [ ] 异常堆栈不含敏感信息

---

### D2 🟡 关键逻辑是否做了控制流混淆？

- [ ] 授权校验逻辑实施**控制流平坦化**
- [ ] 消除显式 `cmp/test + jz` 模式
- [ ] 注入虚假控制流增加分析成本

---

### D3 🟡 授权核心是否做了虚拟化保护？

- [ ] 仅对**授权校验核心**使用 VMP（不要全程序）
- [ ] 评估性能影响（通常下降 10~100 倍）
- [ ] 评估杀软误报风险

---

## E 组 · 工程与流程安全

### E1 🔴 密钥是否纳入版本控制？

**自检方法**：`git log --all -p | grep -i "private\|secret\|key"`

- [ ] 代码库中**无任何密钥材料**
- [ ] 使用 `.gitignore` 排除密钥文件
- [ ] 已配置 secret 扫描（如 gitleaks / trufflehog）

---

### E2 🟠 是否有安全代码审查流程？

- [ ] PR 审查包含安全检查项
- [ ] 关键模块（鉴权 / 加密）需**双人审查**
- [ ] 有"禁止自研密码学"的明确规范

## 快速自查命令

```bash
# 1. 检查是否有硬编码密钥
grep -rniE "(private.?key|secret|aes.?key|password)\s*=" --include=*.cs --include=*.cpp .

# 2. 检查是否有裸 LoadLibrary
grep -rn "LoadLibrary" --include=*.cpp --include=*.c .

# 3. 检查是否有独立布尔判定函数
grep -rniE "bool\s+(is)?(pro|licensed|activated|registered)" --include=*.cs .

# 4. 检查是否调用了 SetDefaultDllDirectories
grep -rn "SetDefaultDllDirectories" --include=*.cpp .

# 5. 检查密钥是否进入版本控制
git log --all -p | grep -iE "BEGIN (RSA |EC )?PRIVATE KEY"
```
