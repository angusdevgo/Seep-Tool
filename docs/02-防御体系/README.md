## 🛡️ 三层纵深防御架构（速览）

```
┌──────────────────────────────────────────────────────────┐
│ 第一层 · 传输与权威层（必需）                              │
│   • 服务端权威原则：核心权益由服务端签发并二次验签            │
│   • 非对称签名（Ed25519）：私钥永不离线                     │
│   • 双向 mTLS + 证书绑定 + 时戳 Nonce 防重放                │
├──────────────────────────────────────────────────────────┤
│ 第二层 · 环境与运行时层（辅助）                             │
│   • SetDefaultDllDirectories 限定加载路径                  │
│   • Authenticode 签名运行时复核                            │
│   • 敏感内存加密存储 + 用毕即时擦除                          │
│   • IPC 消息 HMAC 认证 + 对端进程身份校验                   │
├──────────────────────────────────────────────────────────┤
│ 第三层 · 代码形态与混淆层（提高成本）                        │
│   • 控制流平坦化 + 虚假控制流                               │
│   • 关键判定逻辑 VMP 保护                                  │
│   • 符号剥离 + 敏感字符串动态解密                            │
└──────────────────────────────────────────────────────────┘
```

> ### ⚠️ 关键认知
> **三层是递进关系，不是并列关系。**
> 第一层是**必需**（架构修正）；第二、三层是**辅助**（提高成本）。
> **只做混淆不做架构修正的产品，CWE-602 缺陷依然存在。**

## 📊 加固成本 vs 收益（按缺陷模式）

| 模式 | 修复成本 | 攻击成本（修前 → 修后） |
|:---|:---:|:---|
| 空值短路校验 (Fail-Open) | ★☆☆ | ≈0 → 无法绕过 |
| 动态库加载顺序缺陷 | ★☆☆ | 放一个 DLL → 无法劫持 |
| 明文进程间通信 | ★☆☆ | 伪造状态码 → HMAC 校验失败 |
| 可写全局状态变量 | ★★☆ | 改配置 → 签名凭据不可伪造 |
| 单点布尔裁决 | ★★★ | 改 1 处 → 需攻破签名体系 |
| 硬编码密钥材料 | ★★★ | 替换公钥 → 多点校验拦截 |
| 自研弱校验算法 | ★★★ | 离线生成 → 计算不可行 |

> 💡 **优先修「成本低、收益高」的项** —— 即前 3 行。
