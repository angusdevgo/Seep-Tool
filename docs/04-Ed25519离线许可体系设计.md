# 04 · Ed25519 离线许可体系设计

> 本文提供一套**可直接用于生产环境**的离线授权体系设计方案。
> 采用 **Ed25519 非对称签名**，从根本上消除 CWE-602 缺陷。
>
> 本文代码均为**防御性参考实现**（构建安全授权体系），可直接用于您的产品。

---

## 一、 设计目标

| 目标 | 说明 |
|:---|:---|
| **不可伪造** | 客户端无法自行生成有效凭据（私钥在服务端） |
| **离线可用** | 无需联网即可验证授权 |
| **设备绑定** | 凭据与设备指纹密码学绑定，防跨机复用 |
| **时效可控** | 支持有效期与订阅制 |
| **防重放** | 每次签发含唯一 Nonce |
| **可撤销** | 支持服务端黑名单与强制联网复核 |

---

## 二、 为什么选择 Ed25519

| 对比项 | Ed25519 | RSA-2048 | ECDSA P-256 |
|:---|:---:|:---:|:---:|
| 公钥长度 | **32 B** | 294 B | 64 B |
| 签名长度 | **64 B** | 256 B | ~72 B |
| 签名速度 | **极快** | 慢 | 中 |
| 验签速度 | **快** | 快 | 中 |
| 安全性 | 128-bit | 112-bit | 128-bit |
| 实现复杂度 | **低**（无参数选择风险） | 中 | 高（易误用 nonce） |
| 侧信道抗性 | **强**（常量时间） | 需注意 | **弱**（nonce 复用即泄私钥） |

**结论**：Ed25519 在**安全强度、性能、实现安全性**三方面全面占优，是离线许可体系的首选。

## 三、 体系架构

│  │  私钥 (32 B)  ← 存于 HSM / 离线机器，永不联网               │  │
│  └──────────────────────────────────────────────────────────┘  │
│                            │                                   │
│                            ▼ 签发                              │
│  ┌──────────────────────────────────────────────────────────┐  │

│  │      version:    1,                                      │  │

│  │      tier:       "pro" | "enterprise",                   │  │
│  │      issuedAt:   1735689600,                             │  │

│  │      nonce:      "random-16-bytes",                      │  │
│  │      features:   ["export", "batch", "api"]              │  │
│  │  }                                                       │  │
│  │  Signature = Ed25519.Sign(privKey, License)   // 64 B    │  │
│  └──────────────────────────────────────────────────────────┘  │
│                            │                                   │
│                            ▼ 分发（文件 / 邮件 / 接口）           │
└────────────────────────────┼───────────────────────────────────┘
                             │
                             ▼
┌────────────────────────────────────────────────────────────────┐
│                        客户端（您的软件）                         │
│  ┌──────────────────────────────────────────────────────────┐  │
│  │  公钥 (32 B)  ← 硬编码，多点交叉校验其指纹                  │  │
│  └──────────────────────────────────────────────────────────┘  │
│                            │                                   │
│                            ▼ 验证                              │
│  1. 验签：Ed25519.Verify(pubKey, License, Signature)           │
│  2. 设备绑定：deviceHash == SHA256(本机指纹)                    │
│  3. 有效期：issuedAt ≤ now ≤ expiresAt                         │
│  4. 防回拨：now ≥ 单调时钟记录的最大值                           │
│  5. 功能授权：features 包含所请求的功能                          │

## 四、 载荷结构定义

```csharp
// LicensePayload.cs
using System;
using System.Text.Json;
using System.Text.Json.Serialization;

public sealed class LicensePayload
{
    [JsonPropertyName("v")]   public int      Version    { get; set; } = 1;
    [JsonPropertyName("id")]  public string   LicenseId  { get; set; } = "";
    [JsonPropertyName("dev")] public string   DeviceHash { get; set; } = "";  // Base64
    [JsonPropertyName("tier")]public string   Tier       { get; set; } = "pro";
    [JsonPropertyName("iat")] public long     IssuedAt   { get; set; }        // Unix 秒
    [JsonPropertyName("exp")] public long     ExpiresAt  { get; set; }        // Unix 秒
    [JsonPropertyName("non")] public string   Nonce      { get; set; } = "";  // Base64
    [JsonPropertyName("feat")]public string[] Features   { get; set; } = Array.Empty<string>();

    /// <summary>序列化为确定性字节（用于签名/验签）</summary>
    public byte[] ToCanonicalBytes()
    {
        // ⚠️ 关键：必须使用确定性序列化，保证服务端与客户端字节一致
        var opts = new JsonSerializerOptions
        {
            WriteIndented = false,
            Encoder = System.Text.Encodings.Web.JavaScriptEncoder.UnsafeRelaxedJsonEscaping
        };
        // 字段顺序由 JsonPropertyOrder 或类定义顺序固定
        return JsonSerializer.SerializeToUtf8Bytes(this, opts);
    }

    public static LicensePayload FromBytes(byte[] bytes)
        => JsonSerializer.Deserialize<LicensePayload>(bytes)!;

    public bool IsWithinValidity(DateTimeOffset nowUtc)
    {
        var iat = DateTimeOffset.FromUnixTimeSeconds(IssuedAt);
        var exp = DateTimeOffset.FromUnixTimeSeconds(ExpiresAt);
        return nowUtc >= iat.AddMinutes(-5)   // 容忍 5 分钟时钟偏差
            && nowUtc <= exp;
    }

    public bool Grants(string feature)
        => Array.IndexOf(Features, feature) >= 0;
}
```

## 五、 服务端：签发实现

```csharp
// LicenseIssuer.cs  —— 仅部署在服务端 / 离线签名机
using System.Security.Cryptography;
using System.Text.Json;

public static class LicenseIssuer
{
    /// <summary>从安全存储加载私钥（HSM / 加密文件 / KMS）</summary>
    private static byte[] LoadPrivateKey()
    {
        // ⚠️ 生产环境应从 HSM / KMS 读取，切勿硬编码
        var path = Environment.GetEnvironmentVariable("LICENSE_PRIVKEY_PATH")
                   ?? throw new InvalidOperationException("未配置私钥路径");
        return Convert.FromBase64String(File.ReadAllText(path).Trim());
    }

    public static (string licenseB64, string signatureB64) Issue(
        string deviceHashB64,
        string tier,
        TimeSpan validity,
        string[] features)
    {
        var payload = new LicensePayload
        {
            Version    = 1,
            LicenseId  = Guid.NewGuid().ToString("D"),
            DeviceHash = deviceHashB64,
            Tier       = tier,
            IssuedAt   = DateTimeOffset.UtcNow.ToUnixTimeSeconds(),
            ExpiresAt  = DateTimeOffset.UtcNow.Add(validity).ToUnixTimeSeconds(),
            Nonce      = Convert.ToBase64String(RandomNumberGenerator.GetBytes(16)),
            Features   = features
        };

        byte[] message = payload.ToCanonicalBytes();
        byte[] privKey = LoadPrivateKey();

        // Ed25519 签名（.NET 8+ 内置；旧版本需引入 BouncyCastle 等库）
        byte[] signature = Ed25519.Sign(privKey, message);

        return (Convert.ToBase64String(message),
                Convert.ToBase64String(signature));
    }
}
```

**关键安全要求**：

| 要求 | 说明 |
|:---|:---|
| 🔒 私钥离线 | 签名机物理隔离，永不联网 |
| 🔒 审计日志 | 每次签发记录 `licenseId + deviceHash + 时间` |
| 🔒 速率限制 | 防止批量套取许可证 |
| 🔒 设备绑定 | `deviceHash` 必须来自客户端上报的真实指纹 |
| ⚠️ 撤销列表 | 维护黑名单，客户端定期联网同步 |

## 六、 客户端：验证实现

```csharp
// LicenseVerifier.cs  —— 部署在客户端
using System;
using System.Security.Cryptography;
using System.Text;

public static class LicenseVerifier
{
    // 公钥（公开信息，泄露无害）
    private static readonly byte[] PublicKey = Convert.FromBase64String(
        "MCowBQYDK2VwAyEA...");   // 32 字节 Ed25519 公钥

    // ⚠️ 公钥指纹（用于多点交叉校验，防止公钥被替换）
    private static readonly byte[] PublicKeyFingerprint = Convert.FromHexString(
        "3A7F9C2E...");           // SHA256(PublicKey) 的前 16 字节

    /// <summary>完整验证流程</summary>
    public static LicenseCheckResult Verify(string licenseB64, string signatureB64)
    {
        try
        {
            // ── 步骤 0：公钥完整性交叉校验（防公钥替换）──
            if (!VerifyPublicKeyIntegrity())
                return LicenseCheckResult.Fail("公钥完整性校验失败");

            byte[] message   = Convert.FromBase64String(licenseB64);
            byte[] signature = Convert.FromBase64String(signatureB64);

            // ── 步骤 1：Ed25519 验签 ──
            if (!Ed25519.Verify(signature, message, PublicKey))
                return LicenseCheckResult.Fail("签名验证失败");

            // ── 步骤 2：解析载荷 ──
            var payload = LicensePayload.FromBytes(message);

            // ── 步骤 3：设备绑定校验 ──
            string localHash = Convert.ToBase64String(ComputeDeviceHash());
            if (!CryptographicOperations.FixedTimeEquals(
                    Encoding.ASCII.GetBytes(localHash),
                    Encoding.ASCII.GetBytes(payload.DeviceHash)))
                return LicenseCheckResult.Fail("设备绑定不匹配");

            // ── 步骤 4：有效期校验 + 防时钟回拨 ──
            var now = GetMonotonicUtcNow();
            if (!payload.IsWithinValidity(now))
                return LicenseCheckResult.Fail("许可证已过期");

            // ── 步骤 5：撤销列表校验（可选，需联网）──
            if (IsRevoked(payload.LicenseId))
                return LicenseCheckResult.Fail("许可证已被撤销");

            return LicenseCheckResult.Ok(payload);
        }
        catch (Exception ex)
        {
            return LicenseCheckResult.Fail("许可证格式错误");
        }
    }

    /// <summary>公钥指纹多点交叉校验</summary>
    private static bool VerifyPublicKeyIntegrity()
    {
        // 在多个不相关的位置重复计算并比对
        // 攻击者必须同时替换所有校验点才能绕过
        byte[] actual = SHA256.HashData(PublicKey);
        for (int i = 0; i < PublicKeyFingerprint.Length; i++)
        {
            if (actual[i] != PublicKeyFingerprint[i]) return false;
        }
        return true;
    }

    /// <summary>计算设备指纹</summary>
    private static byte[] ComputeDeviceHash()
    {
        // 组合多个硬件标识（避免单一标识被伪造）
        var components = string.Join("|",
            GetMachineGuid(),      // 注册表 MachineGuid
            GetSystemVolumeSerial(),
            GetCpuIdentifier(),
            GetMotherboardSerial());

        return SHA256.HashData(Encoding.UTF8.GetBytes(components));
    }

    /// <summary>单调时钟（防系统时间回拨）</summary>
    private static DateTimeOffset GetMonotonicUtcNow()
    {
        var wallClock = DateTimeOffset.UtcNow;
        var stored = LoadLastKnownTime();       // 从加密存储读取历史最大值

        if (wallClock < stored)
        {
            // 检测到时钟回拨 → 使用历史最大值，并记录异常
            LogClockTamper(wallClock, stored);
            return stored;
        }

        SaveLastKnownTime(wallClock);           // 更新历史最大值
        return wallClock;
    }
}
```

## 七、 与业务逻辑的集成（关键！）

> **这是修复 CWE-602 的核心步骤：消除独立的布尔判定出口。**

```csharp
// ❌ 错误做法：先判后用（存在可篡改的中间状态）
if (LicenseManager.IsPro())
{
    ExportToPdf();     // 攻击者只需让 IsPro() 返回 true
}

// ✅ 正确做法：校验与执行合一，无中间状态
public static class FeatureGate
{
    private static LicensePayload? _entitlement;

    public static void ExecuteGated(string feature, Action action)
    {
        // 每次调用都重新验签，不缓存布尔结果
        var payload = LicenseStore.LoadAndVerify();
        if (payload is null)
            throw new LicenseRequiredException(feature);

        if (!payload.Grants(feature))
            throw new FeatureNotEntitledException(feature);

        // 直接执行，不暴露"是否有权限"这个中间状态
        action();
    }
}

// 业务代码
FeatureGate.ExecuteGated("export.pdf", () => ExportToPdf());
```

**改进要点**：

| 反例特征 | 正例特征 |
|:---|:---|
| 独立 `IsPro()` 函数 | 无独立判定出口 |
| 先判后用，存在中间布尔状态 | 校验与执行合一 |
| 判定结果可缓存 | 每次重新验签 |
| 单点校验 | 多点交叉校验 |

## 八、 部署检查清单

### 服务端

- [ ] 私钥存于 HSM / 离线签名机，**从未出现在客户端或代码库**
- [ ] 签名操作有完整审计日志（`licenseId + deviceHash + 时间戳`）
- [ ] 有速率限制，防止批量套取
- [ ] 维护撤销黑名单并支持客户端同步
- [ ] 私钥有备份与轮换预案（轮换需客户端支持多公钥）

### 客户端

- [ ] 仅内置**公钥**，无任何私钥材料
- [ ] 公钥指纹在**多个不相关位置**交叉校验
- [ ] 验签与业务执行**合一**，无独立布尔判定出口
- [ ] 实现**单调时钟**，抵抗系统时间回拨
- [ ] 敏感数据用毕**立即擦除**
- [ ] 许可证文件本身加密存储
- [ ] 结合二进制完整性自检（防止验签代码被 patch）

### 密钥轮换预案

```csharp
// 客户端应支持多个公钥，以便服务端轮换
private static readonly byte[][] TrustedPublicKeys = new[]
{
    Convert.FromBase64String("...key_v1..."),
    Convert.FromBase64String("...key_v2..."),   // 新公钥
};

// 验签时逐个尝试
private static bool VerifyAny(byte[] msg, byte[] sig)
{
    foreach (var key in TrustedPublicKeys)
        if (Ed25519.Verify(sig, msg, key)) return true;
    return false;
}
```

## 九、 常见误用与避坑

| 误区 | 后果 | 正确做法 |
|:---|:---|:---|
| 公钥硬编码但无完整性校验 | 公钥被替换 → 体系失效 | 公钥指纹多点交叉校验 |
| 序列化不确定（字段顺序变化） | 验签失败或可被构造 | 使用固定字段顺序的确定性序列化 |
| 使用 `==` 比较哈希 | 时序攻击 | `CryptographicOperations.FixedTimeEquals` |
| 只校验签名不校验有效期 | 永久有效 | 强制校验 `exp` |
| 只校验签名不绑定设备 | 一码多机 | `deviceHash` 密码学绑定 |
| 用系统时间做时效判定 | 时间回拨绕过 | 单调时钟 + 历史最大值 |
| 缓存验签结果 | 中间状态可篡改 | 每次重新验签 |
| 保留独立的 `IsPro()` 出口 | CWE-602 残留 | 校验与执行合一 |
